# Compiled CSS logical blocks

Branch: `codex/compiled-logical-blocks`, starting from research commit
`77c2e16c`. The user authorized the narrow planner/action extension and deferred
the durable structured-input direction. This is the first production slice of
the [logical-block proposal](logical_block_integration.md).

## Implementation

```python
program = clifft.compile(text, logical_blocks=True)
print(program.num_css_blocks, program.peak_active_width)
samples = clifft.sample(program, 2048, seed=170, threads=1)
```

The flag defaults to false. Compilation first builds the ordinary plan without
allocating its dense worker. Only plans above ten active coordinates are
considered. A source recognizer proves the CSS boundary and complete physical
interval, then compares compiled factor-gather work with ordinary dense-state
traversals. Unsupported or unprofitable candidates retain the ordinary plan.
This work comparison is a conservative heuristic, not a universal crossover
model. The public count makes selection observable.

Each block consumes and returns the ordinary executor's two logical
coefficients. Its incoming syndrome frame and four Pauli-fault layers are
ordinary compiled affine expressions. Fixed factor tables contract the
T-conjugated all-Y measurement and the actual full CSS projection. True branch
symbols carry the physical sector between blocks; separate readout flips affect
reported records only. The existing executor owns noise, RNG, records, detector
and observable writes, fixed-fault conditioning, and postselection.

Plans and contraction workspaces are prepared once, and reused for all shots.
No Python factor compiler, serialized research plan, runtime tableau, graph
planning, or per-shot compilation is involved. The new kernel preserves coherent
cross terms and is compiled without fast-math reassociation.

## Benchmark corpus and evidence

The committed `tools/bench/fixtures/css_five_check_d{3,5,7,9}.stim` controls have
7/19/37/61 data wires, five complete checks, four depolarizing layers per check,
readout noise at probability 0.001, detectors, and a final logical measurement.
They are generated by the independently checked research `Sequence` generator.
They use ideal encoded preparation and direct CSS measurements; they are not
full fault-tolerant cultivation protocols. A nonzero check-difference detector
can occur even with no physical faults in the larger synthetic controls.

Run:

```bash
python tools/bench/measure_css_blocks.py --shots 2048 --repeats 3 --output results.json
```

The raw [measurements](compiled_css_blocks_data.json) include circuit hashes,
compile times, every timed batch, active width, and selected block count.
The test uses the normal Python API with optimized HIR, one CPU worker and
scalar batching, three batches of 2,048 shots per program after warmup.
Compilation is separate from sampling. Hardware: exe.dev VM on AMD EPYC 9554P;
Release native CPU build, OpenMP available, one requested sampling thread.

| Control | Ordinary time/shot | Opt-in time/shot | Selected blocks |
|---|---:|---:|---:|
| 37 data, five checks | 14.99 ms | 1.21 ms | 5 |
| 61 data, five checks | Not allocated | 4.29 ms | 5 |

The matched 37-data comparison is **12.4x faster**. Compiling the contracted
program takes about 4.0 ms at 37 data and 8.9 ms at 61 data. Small controls have
identical selected execution paths; fluctuations in their short timings are
measurement variation, not a logical-block speedup.

The 37-data control provides a direct ordinary-versus-contracted comparison.
The 61-data ordinary plan reaches width 31: coefficients alone require 32 GiB,
before measurement scratch, records, and allocator overhead. It is not sampled
on this VM. The contracted workers use 11,936 and 23,968 bytes of coefficient
contraction scratch respectively, plus immutable factor tables, two logical
coefficients, symbols, records, and normal executor/output storage. These scratch
figures are not total RSS.

Small 7/19-data controls retain ordinary execution. Original MSC d3/d5 injection
and cultivation fixtures also retain ordinary execution and seeded records.
No authors' full MSC7 artifact has become available. Reconstructed f5/f7 fold
circuits require a different quadratic-phase certificate and are not selected
by this first production path. These results establish a practical gain for
the controlled repeated-check family, not best-in-class status or a full MSC7
speedup.

  terminal axes match ordinary physical-gate Clifft log probabilities. The
  histories include dense faults in all four layers and repeated frame handoffs.
- Six committed Aer elementary-gate witnesses cover complete five-check

  These are independent physical-gate probabilities, not factor-kernel outputs.
- Three complete 61-data X/Y/Z histories are re-evaluated with the independent
  coherent-stabilizer CH reference and replayed by the production executor.
  Regenerate with `python tools/profile/export_css_ch_histories.py`. This extends
  probability coverage to the largest state without allocating a dense oracle.
- Stim independently evaluates original detector/observable declarations on
  reported records from the public 37/61-data programs.
- Tests cover asymmetric readout, unreachable records, Clifford and T-dagger
  initial states, malformed certificates and branch ownership, factor budgets,
  seeded shot parallelism, fixed-fault sampling, postselection, custom-pass
  fallback, small and real-fixture fallback, and explicit packed-mode rejection.
- An isolated native test forbids `new`/`new[]` during repeated noisy execution
  on both large controls. Kernel and dispatch storage are preallocated.
- Assertion-enabled native suite: 942 tests pass. Full Python suite: 1,418 pass,
  seven skip. Repository-wide pre-commit checks pass.

The earlier standalone research coverage additionally includes exhaustive
local fault-map matrix checks and more complete CH replays. Those support
the mathematics; they do not substitute for the production integration checks
above.

## Current limits and next useful extension

The recognizer accepts an ideal Clifford prefix with at most one T, repeated
full-data T/all-Y/T-dagger checks and complete balanced CSS projections, then
one all-data logical X/Y/Z measurement. It certifies one encoded qubit, no
spectators, and the same positive CSS generators throughout. Single-qubit Pauli
channels and immediate measurement readout noise are supported. Limits are
63 data wires, 31 generators per family, and bounded factor-table work/storage.

Feedback, ancilla extraction, growth, arbitrary suffixes, expectation probes,
non-Pauli instruments, retained source maps, and automatic syndrome
normalization are outside this certificate. Public compilation falls back
before allocating a worker. This does not guarantee that the ordinary fallback
will fit memory. Custom HIR passes retain their original semantics and bypass
recognition. Explicit packed batches and HIP reject block actions; instrument
continuations cannot carry them. Automatic CPU sampling uses scalar workers
and can parallelize independent shots.

The next physics extension would be a separately proved fold/quadratic-phase
block for reconstructed f7, or an interval certificate for real growth/ancilla
circuits when suitable coverage exists. Neither requires changing the current
ordinary state representation. A new authors' large circuit would be especially
valuable for deciding which extension earns its complexity.
